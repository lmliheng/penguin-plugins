# 写稿规范（横屏长视频 · 写手必读）

你要产出的东西只有一份：`lessons/<集 id>/script.json`（外加实跑验证脚本 `facts/<集 id>.py` 与 `facts/<集 id>.json`，再写一份 `lessons/<集 id>/NOTES.md`）。
**不要**跑 `tts.py` / `render.mjs` / `build.py` —— 配音与渲染由主 agent 统一做（`frames/` 只有一份，两个进程同时跑会互相删帧）。

动笔前先读四份现成的东西：`example/script.json`（十一种幕型各一幕的骨架）、`lib/deck-light.html`（幕型模板与字段的唯一权威）、`tools/check_script.py`（它会怎么挑你的错）、以及任意一集成稿。

Windows 上 Python 调用一律加 `PYTHONUTF8=1`。

---

## 一、整体目标

每集一个专题，**15 分钟左右**（旁白净时长；语速实测 5.8 字/秒 → **总旁白 4800–5200 字**，幕数 20–26）。

一集的结构（**必须按这个骨架**，因为观众是靠骨架记住套路的）：

1. **开场**（1 幕 `title`）：这个专题解决什么形状的问题，一句话立住。
2. **朴素解为什么慢**（2–3 幕 `points`/`flow`）：先讲暴力，讲清慢在哪（复杂度实算），才有后面的快。
3. **模板/不变量**（2–3 幕 `points`/`flow`）：把解法抽象成一条不变量或一个模板。
4. **好题秒杀**（8–12 幕，每题 1–2 幕 `code`/`array`/`grid`/`graph`）：挑 5–6 道经典题，
   每题讲「题目信号 → 套哪个模板 → 代码 → 复杂度」。要有「看到 X 就想到 Y」的句子。
5. **语法层面**（3–4 幕）：这一集用到的语言细节，讲透（见第四节）。
6. **套路总结 + 下集预告**（1 幕 `outro`）。

**深度要求**：不能只报答案。每个模板都要给出**为什么对**（单调性 / 循环不变量 / 摊还分析 / 归纳法 / 反证），
并举一个「不用模板就会错」的反例。

**可视化是硬指标**：一集里至少 **6 幕**是可视化幕型（`array` / `grid` / `stack` / `tree` / `graph` / `groups` / `flow`），
纯文字与代码的幕不超过一半。这是用户的硬意见（「没有图像，没有算法流程演示」），别再犯。

## 二、`script.json` 的 schema（严格遵守）

```json
{
  "id": "ep05-window-prefix",
  "series": "算法专题",
  "episode": "第 5 集 · 滑动窗口与前缀和",
  "brand": "算法专题 · 进阶 6 集",
  "size": "1920x1080",
  "deck": "deck-light.html",
  "wm": "@GitHub/your-handle",
  "voice": "zh-CN-YunxiNeural",
  "rate": "+18%",
  "gap": 0.3,
  "scenes": [ ... ]
}
```

顶层字段照抄上面这份，只改 `id` / `episode` / `brand` / `wm`。**`size` / `deck` / `voice` / `rate` / `gap` 不许改**——
`size: 1920x1080` 与 `deck: deck-light.html` 决定画布与版式，少一个渲染就会去找不存在的 `lib/deck.html` 而报错。

每一幕的公共字段：

| 字段 | 要求 |
| --- | --- |
| `id` | `s1` `s2` … 递增，仅本幕用 |
| `type` | 只能用下面这 **11 种** |
| `narration` | 这一幕要说的话（**旁白**），200–300 字，写口语，不写书面语 |

**白底横屏版（`deck-light.html`）只实现了这些幕型**：`title` / `points` / `code` /
`array` / `grid` / `stack` / `tree` / `graph` / `groups` / `flow` / `outro`。
老黑底版的 `math` 和 `source` 在这份版式里**没有模板，写了直接崩**——要「公式/不变量」用 `flow` 或 `points`，
要「代码 + 三条观察」用两幕（`code` + `points`）。

### 通用规则（所有带 `steps` 的幕型）

- 每一步**必须有 `cue`**：一句关键词，**必须原样出现在同一幕的 `narration` 里**（一个标点都不能差）。
  配音合成后主 agent 会用它把这一步标定到秒，动画就跟着讲解走——**不要手写时间**。
- 每一步 `verdict` ≤ 12 字，写在这一刻的读数区（「还不到 7，继续」这种）。
- 一集里每幕的步数 8–14 步比较合适（少于 8 步画面会长时间不动）。
- **每一步的状态必须等于真实轨迹**：`facts/<集 id>.py` 里要按屏幕上那段代码重算一遍，
  逐字段比对，全等才算过。

### `title`（只在第 1 幕）

```json
{ "id":"s1","type":"title","kicker":"算法专题 · 第 5 集","title":"滑动窗口","sub":"窗口不是一段区间，是一个不变量","tags":["连续","摊还","线性"],"narration":"..." }
```

- `title` ≤ 8 字（最好 4–6 字）；`sub` ≤ 24 字；`tags` 正好 3 个，每个 ≤ 6 字

### `points`（要点/对比）

```json
{ "id":"s2","type":"points","kicker":"01 · 先看暴力","title":"两层循环的代价","items":["……","……","……"],"takeaway":"","narration":"..." }
```

- `items` **正好 3 条**，每条 ≤ 44 字（超过会折行）；可以用 `<em>关键词</em>` 标蓝（每幕最多 2 处）
- `takeaway` 可选，一句话结论条

### `code`（代码）

```json
{ "id":"s4","type":"code","kicker":"03 · 秒题","title":"LC 209 长度最小的子数组","file":"leetcode_209.py","code":"left = 0\nfor right, x in enumerate(nums):\n    ...","code_reveal":4,"narration":"..." }
```

- `code` 用 `\n` 分行；**每行 ≤ 84 个西文字符**；**最多 9 行**；缩进 4 空格；必须是能跑的代码
- `code_reveal`：逐行出现的秒数，写 3–5

### `array`（一维数组 + 两个指针 + 读数芯片）— 最常用的可视化

```json
{ "id":"s4","type":"array","kicker":"03 · 走一遍","title":"右指针只往右，左指针只往右",
  "values":[2,3,1,2,4,3],"lblL":"L","lblR":"R","hideWin":false,
  "chips":[{"k":"dp","label":"dp 值"},{"k":"best","label":"当前最优"}],
  "steps":[
    { "cue":"右指针先落在第一个数上","l":0,"r":0,"vals":{"dp":2,"best":0},"from":[0],"verdict":"还不到 7" }
  ], "takeaway":"", "narration":"..." }
```

- `values` 2–13 个数字（横屏一行放得下 13 格）；`l` / `r` 是本步两个指针的下标（0 起，`l ≤ r`）
- `lblL` / `lblR` 可选，指针上的字母，默认 `L` / `R`（DP 里可以写成 `i` / `j`）
- `hideWin` 可选：`true` 就不画那个蓝色窗口框（讲 DP、前缀和时用）
- **两种芯片写法，二选一**：
  - 不写 `chips`：芯片固定是「窗口和 / 窗口长度 /（目标）/（最短）」，由 `sum`、`len`、
    顶层 `target`、顶层 `best` 驱动（滑动窗口题就用这种）
  - 写了 `chips`：芯片就是 `chips` 里列的（2–5 个），每个 `k` 的值从本步的 `vals` 里取（DP、前缀和用这种）
- `from` 可选：本步要高亮的「来源」格子下标（讲 `dp[i]` 从谁推出来时用）
- 顶层 `target` / `best` 可选，只有写老式芯片时才用

### `grid`（二维表格逐格填）

```json
{ "id":"s9","type":"grid","kicker":"06 · 填表","title":"从左上角一路填到右下角",
  "rows":["a","b","c"],"cols":["a","b","c"],
  "chips":[{"k":"v","label":"dp 值"}],
  "steps":[
    { "cue":"第一行第一列先填零","r":0,"c":0,"vals":{"v":0},"from":[],"verdict":"边界先立住" },
    { "cue":"相等的字符","r":1,"c":1,"vals":{"v":1},"from":[[0,0]],"verdict":"左上角加一" }
  ], "takeaway":"", "narration":"..." }
```

- `rows` / `cols` 是数据区的行标题与列标题（左上角会自动留空），**各 ≤ 6 个、每个 ≤ 4 字**
- `r` / `c` 是数据区下标（0 起）；`vals` 与 `from`（要圈出来的已填格子 `[[r,c],…]`）同 `array`
- 填过的格子保留数值，看起来是「一张表被逐步填满」

### `stack`（调用栈 / 递归栈）

```json
{ "id":"s5","type":"stack","kicker":"03 · 栈里发生了什么","title":"一路压到出口，再一路弹回来",
  "frames":[{"f":"f(3)","s":"n=3"},{"f":"f(2)","s":"n=2"},{"f":"f(1)","s":"n=1"},{"f":"f(0)","s":"出口"}],
  "steps":[
    { "cue":"一直压到零","d":3,"verdict":"栈深 4，还没算出一个值" },
    { "cue":"零这一层先返回","d":3,"ret":"1","verdict":"f(0) 交出 1" }
  ], "takeaway":"", "narration":"..." }
```

- `frames` 从**栈底到栈顶**（数组第 0 个是最早压进去的）；`d` = 本步可见到第几层（0 起，含）
- `ret` 可选：本步右侧显示「返回 …」
- 3–8 帧，帧里的 `f` ≤ 12 字、`s` ≤ 10 字

### `tree`（递归树 / 决策树）

```json
{ "id":"s6","type":"tree","kicker":"04 · 决策树","title":"每个节点都是一次选择",
  "nodes":[{"id":"r","p":null,"t":"[]"},{"id":"a","p":"r","t":"[1]"}],
  "steps":[
    { "cue":"先什么都不选","open":["r"],"verdict":"根节点是空集" },
    { "cue":"这个分支试不下去","open":["r","a"],"prune":["a"],"verdict":"剪掉" }
  ], "takeaway":"", "narration":"..." }
```

- `p` 是父节点 id（根写 `null`）；布局自动算，**节点 ≤ 15 个、层数 ≤ 4**，`t` 每个 ≤ 10 字
- `open`：本步要显示（已经展开）的节点 id；`prune`：本步标记为剪掉的节点（灰掉打叉）
- 同一层里按 `nodes` 数组顺序左右排开

### `graph`（图 / 网格图的节点与边）

```json
{ "id":"s8","type":"graph","kicker":"05 · 走一遍图","title":"BFS 一圈一圈往外扩",
  "nodes":[{"id":"A","t":"A","x":18,"y":30},{"id":"B","t":"B","x":48,"y":14}],
  "edges":[["A","B"],["B","C"]],
  "steps":[
    { "cue":"先把零号节点入队","visit":["A"],"cur":"A","edge":[],"queue":["B","C"],"verdict":"队列里两个" }
  ], "takeaway":"", "narration":"..." }
```

- `x` / `y` 是画布里的百分比位置（0–100，节点圆心），**自己排布好，别让节点或文字重叠**，节点 ≤ 10 个
- `edges` 是无向边的 `[from, to]` 数组（有向图自己按方向排序即可，画面不画箭头）
- `visit`：已经访问过的节点 id（上色）；`cur`：本步正在处理的节点（高亮脉冲）；
- `edge`：本步要高亮的边 `[from, to]`（可省）；`queue`：底部队列/栈的当前内容（可省，**≤ 8 项**，每项 ≤ 4 字）

### `groups`（并查集：集合的合并）

```json
{ "id":"s4","type":"groups","kicker":"03 · 合并","title":"两个集合并成一个",
  "steps":[
    { "cue":"一和二是一伙的","groups":["{1}","{2}","{3}","{4}"],"hi":[0,1],"merge":[0,1],"verdict":"要合这两个" }
  ], "takeaway":"", "narration":"..." }
```

- 每一步给出**当时的全部集合**（`groups`，2–6 个，每个 ≤ 10 字），以及 `hi`（本步在讲哪几个，下标）
  与 `merge`（本步要合并哪两个，下标，可省）；集合顺序保持稳定，看起来才是「合并」而不是「重排」
- 注意最少要 **2 个集合**：只剩一个集合的那一步画不出来，把「合并成一组」放在下一步讲

### `flow`（流程卡片，讲「为什么慢 / 为什么不亏」）

```json
{ "id":"s5","type":"flow","kicker":"04 · 为什么不亏","title":"两个指针加起来，只走两倍的 n",
  "nodes":[{"t":"右指针","s":"每个位置只经过一次"},{"t":"左指针","s":"每个位置也只经过一次"},{"t":"合计 2n","s":"每个元素进出各一次"}],
  "steps":[{"cue":"右指针把数组从头扫到尾","i":0},{"cue":"总步数是两倍的 n","i":2}],
  "takeaway":"每个元素平均只被碰两次，这就是摊还", "narration":"..." }
```

- `nodes` 2–4 个，`t` ≤ 6 字、`s` ≤ 14 字；`steps` 里 `i` 是当前讲到第几个卡片（0 起）

### `outro`（最后一幕）

```json
{ "id":"s22","type":"outro","kicker":"下一集","title":"动态规划","sub":"状态定义对了，转移自己会写","cta":"关注抖音号 your-handle","narration":"...（结尾一定要把 CTA 念出来）" }
```

## 三、旁白怎么写（这是成片质量的头号因素）

1. **口语**：像讲课，不像教科书。「我们来看」而不是「本文分析」。短句为主，一句话一个意思。
2. **字数**：每幕 200–300 字，按 5.8 字/秒估时长，全片合计控制在 4800–5200 字。
3. **数字与符号要写成念得出的样子**（字幕会显示英文字母，但旁白是给 TTS 读的）：
   - 复杂度：写「O n」「O n log n」「O n 平方」「摊还 O 1」（屏幕上是 `O(n)`、`O(n²)`）
   - 代码标识符：写「nums 的切片赋值」「用 left 和 right 两个指针」，别写 `nums[:] = ...` 这种符号串
   - 数字：写「两千零一」「百分之七十」，别写「2001」「70%」
   - 不要出现 `→` `≤` `×` `*` `%` `//` 这类符号，也不要出现表情；不要用括号套括号（`check_script.py` 会拦）
4. **不要念代码**：代码在屏幕上，旁白讲「这段在干什么、为什么这么写」。
5. 每幕结尾留一句过渡（「那问题来了」「这就是第一个坑」），让 20 多幕连成一条线。

## 四、语法层面要讲什么（每集至少 3 处，讲透，别点到为止）

不是「语法小贴士」，而是**会影响正确性或效率的语义**。每集从下面的池子里挑 3–5 个，结合本集题目讲：

- 可变对象与引用：`nums[:] = ...` 就地改 vs `nums = ...` 换名字；函数参数传的是引用；
  「原地修改」为什么要求前者
- 循环结构：`for x in nums` 拿的是值、`enumerate` 拿的是 (下标, 值)；遍历中删除元素的坑；
  `while` 与索引的边界；`range(len(nums)-1, -1, -1)` 倒着走
- 复杂度陷阱：`x in list` 是 O(n)、`list.remove` / `list.insert(0, x)` 是 O(n)、
  `s += t` 在循环里是 O(n²)、`set`/`dict` 查找是 O(1)（哈希冲突时不是）
- 标准库：`collections.Counter` / `defaultdict` / `deque`、`heapq`、`bisect`、`itertools.accumulate`、
  `math.inf`，各自**为什么**比手写快
- 切片与拷贝：`a[:]` 浅拷贝、`a[::-1]` 反转、切片是 O(k)、二维 `[[0]*n]*m` 的经典坑
- 函数与作用域：LEGB、闭包捕获变量（`lambda` 循环变量坑）、`nonlocal`、默认参数是可变对象的坑、
  `sys.setrecursionlimit` 与 `RecursionError`
- 数值：整数不溢出但会变慢（大整数）、`//` 对负数向下取整、`divmod`、`float('inf')`

写法要求：**先说现象，再说语义，最后给一个会踩坑的例子**（例子要能在幕上跑出来）。

## 五、所有数字必须真跑（硬要求）

写 `facts/<集 id>.py`，跑通后产出 `facts/<集 id>.json`：

- 片中出现的**每个**代码片段，都要用题目给的样例跑一遍，断言结果正确（`assert`），
  把真实返回值写进 json（字幕/要点里引用的输出必须是这里出来的）
- 复杂度声称要能给依据：比如计数量级（`n = 10**5` 时的循环次数）、或用 `time.perf_counter()` 实测
  两个写法的**真实耗时比**
- 需要「反例」的地方（不用模板就错），反例也跑出来
- `array` / `grid` 的每一步，都要用真实代码重算轨迹并逐字段比对（`l`/`r`/`vals`/填表位置）
- `facts/<集 id>.json` 结构自定，但每条要写清 `key`、`value`、`怎么得到的`

另写 `lessons/<集 id>/NOTES.md`（十几行即可）：这集讲了什么、实跑验证了哪些结论、还有哪些没验证的猜想。

## 六、自检（提交前自己过一遍）

一条命令跑完前几条：`PYTHONUTF8=1 python tools/check_script.py lessons/<集 id>`（必须打印「自检通过」再交付）。
它同时会查：幕型是不是白底版实现了的那 11 种、可视化幕够不够 6 幕、每一步的字段有没有缺、
`from` / `r` / `c` / `d` / `open` / `prune` / `visit` / `hi` 这些下标有没有越界、cue 有没有原样出现在旁白里。

字数与节奏可以放宽（**只对 3–5 分钟的短样片或示例稿**，正式一集不要放宽）：

```bash
python tools/check_script.py lessons/<集 id> --narr=40,200 --total=700,1400 --scenes=5,12 --viz=5
```

- [ ] `script.json` 是合法 JSON（`python -c "import json;json.load(open(...))"` 能过）
- [ ] 顶层写了 `"size": "1920x1080"` 和 `"deck": "deck-light.html"`
- [ ] 旁白总字数 4800–5200，幕数 20–26，每幕旁白 200–300 字
- [ ] **至少 6 幕是可视化幕型**（`array`/`grid`/`stack`/`tree`/`graph`/`groups`/`flow`）
- [ ] 每一步都有 `cue`，且 cue **原样**出现在同一幕 `narration` 里
- [ ] `array` 的 `l ≤ r`；`from` 的下标在数组范围内；`vals` 的键与 `chips` 的 `k` 一一对应
- [ ] `grid` 的 `r` < 行数、`c` < 列数；`tree` 的节点 ≤ 15、层数 ≤ 4；`graph` 的节点 ≤ 10 且不重叠、`queue` ≤ 8 项
- [ ] 每行代码 ≤ 84 字符、≤ 9 行；`points` 每条 ≤ 44 字且正好 3 条
- [ ] `title` 幕的 `title` ≤ 8 字，`tags` 正好 3 个；`outro` 的旁白念了「关注抖音号」
- [ ] 旁白里没有 `%`、`≤`、`→`、`*`、`//` 这类符号，数字都写成中文读法
- [ ] `facts/<集 id>.py` 跑通，json 里每个数字都有出处；轨迹比对全等
- [ ] 语法讲解至少 3 处，且都是「影响正确性或效率」的语义级细节
